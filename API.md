# Meawle API Documentation

## 📋 Обзор

Meawle предоставляет REST API для управления пользователями, кошками и породами кошек. Все API эндпоинты версионированы и доступны по префиксу `/api/v1`.

## 🔐 Аутентификация

Для доступа к защищенным эндпоинтам требуется JWT токен, который можно получить через эндпоинт `/api/v1/auth/login`. Токен должен передаваться в заголовке:

```
Authorization: Bearer <your-jwt-token>
```

## 📊 Формат ответов

Все API эндпоинты возвращают ответы в стандартном формате:

### Успешный ответ
```json
{
  "is_ok": true,
  "result": {
    // Данные ответа
  }
}
```

### Ответ с ошибкой
```json
{
  "is_ok": false,
  "error": "Описание ошибки"
}
```

## 🔐 Аутентификация

### `POST /api/v1/auth/register`
Регистрация нового пользователя.

**Тело запроса:**
```json
{
  "email": "user@example.com",
  "password": "password123",
  "is_admin": false
}
```

**Поля:**
- `email` (string, required) - Email пользователя
- `password` (string, required, min 6 символов) - Пароль
- `is_admin` (boolean, optional) - Флаг администратора

**Ответ:**
```json
{
  "is_ok": true,
  "result": {
    "id": 1,
    "email": "user@example.com",
    "is_admin": false,
    "can_edit": false
  }
}
```

**Коды статусов:**
- `201 Created` - Успешная регистрация
- `400 Bad Request` - Неверный формат данных
- `409 Conflict` - Email уже существует

---

### `POST /api/v1/auth/login`
Вход в систему и получение JWT токена.

**Тело запроса:**
```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

**Поля:**
- `email` (string, required) - Email пользователя
- `password` (string, required) - Пароль

**Ответ:**
```json
{
  "is_ok": true,
  "result": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": 1,
      "email": "user@example.com",
      "is_admin": false,
      "can_edit": true
    }
  }
}
```

**Коды статусов:**
- `200 OK` - Успешный вход
- `400 Bad Request` - Неверный формат данных
- `401 Unauthorized` - Неверные учетные данные

Обновление пользователя. Требуется аутентификация. Пользователь может обновлять только свой профиль, администраторы могут обновлять любые профили.

```json
  "is_admin": true
}
```

**Поля (все опциональны):**
- `email` (string) - Новый email
- `password` (string, min 6 символов) - Новый пароль
- `is_admin` (boolean) - Флаг администратора

**Ответ:**
```json
{
  "is_ok": true,
  "result": "User updated successfully"
}
```

**Коды статусов:**
- `200 OK` - Успешное обновление
- `400 Bad Request` - Неверный формат данных
- `401 Unauthorized` - Требуется аутентификация
- `403 Forbidden` - Доступ запрещен
- `404 Not Found` - Пользователь не найден
- `409 Conflict` - Email уже существует

## 🔧 Ошибки

### Общие коды ошибок

- `400 Bad Request` - Неверный формат запроса или данные
- `401 Unauthorized` - Требуется аутентификация
- `403 Forbidden` - Доступ запрещен (недостаточно прав)
- `404 Not Found` - Ресурс не найден
- `409 Conflict` - Конфликт данных (например, email уже существует)
- `500 Internal Server Error` - Внутренняя ошибка сервера

### Формат ошибок

Все ошибки возвращаются в стандартном формате:

```json
{
  "is_ok": false,
  "error": "Описание ошибки"
}
```

---

## 📝 Примечания

- Все даты возвращаются в формате ISO 8601
- Все ID являются целыми числами
- Поля `can_edit` указывают, может ли текущий пользователь редактировать ресурс
- Администраторы имеют полный доступ ко всем ресурсам
- Пользователи могут редактировать только свои собственные ресурсы
