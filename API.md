# Meawle API Documentation

## 📋 Обзор

Meawle предоставляет REST API для управления пользователями, кошками, породами кошек и домиками для кошек. Все API эндпоинты версионированы и доступны по префиксу `/api/v1`.

## 🔐 Аутентификация

Для доступа к защищенным эндпоинтам требуется JWT токен, который можно получить через эндпоинт `/api/v1/auth/login`. Токен должен передаваться в заголовке:

```
Authorization: Bearer <your-jwt-token>
```

## 📊 Формат ответов

Все API эндпоинты возвращают ответы в стандартном формате:

### Успешный ответ
```json
{
  "is_ok": true,
  "result": {
    // Данные ответа
  }
}
```

### Ответ с ошибкой
```json
{
  "is_ok": false,
  "error": "Описание ошибки"
}
```

## 🔐 Аутентификация

### `POST /api/v1/auth/register`
Регистрация нового пользователя.

**Тело запроса:**
```json
{
  "email": "user@example.com",
  "password": "password123",
  "is_admin": false
}
```

**Поля:**
- `email` (string, required) - Email пользователя
- `password` (string, required, min 6 символов) - Пароль
- `is_admin` (boolean, optional) - Флаг администратора

**Ответ:**
```json
{
  "is_ok": true,
  "result": {
    "id": 1,
    "email": "user@example.com",
    "is_admin": false,
    "can_edit": false
  }
}
```

**Коды статусов:**
- `201 Created` - Успешная регистрация
- `400 Bad Request` - Неверный формат данных
- `409 Conflict` - Email уже существует

---

### `POST /api/v1/auth/login`

**Тело запроса:**
```json

```

**Поля:**

**Ответ:**

  "is_ok": true,

## 🏠 Домики для кошек

### Обзор
API для управления домиками для кошек. Домики имеют название и вместимость. Кошек можно помещать в домики, если есть свободные места. Один кот может находиться только в одном домике.

### Модели

#### CatHouse
```json
{
  "id": 1,
  "name": "Большой дом",
  "capacity": 5,
  "current_occupancy": 0,
  "available_spaces": 5,
  "user_id": 1,
  "created_at": "2024-01-01T00:00:00Z",
  "updated_at": "2024-01-01T00:00:00Z",
  "can_edit": false
}
```

#### CatHouseCreateRequest
```json
{
  "name": "Новый домик",
  "capacity": 3
}
```

#### CatHouseUpdateRequest
```json
{
  "name": "Обновленное название",
  "capacity": 4
}
```

#### CatHouseOccupancyRequest
```json
{
  "cat_house_id": 1
}
```

#### CatHouseOccupancyResponse
```json
{
  "id": 1,
  "cat_id": 1,
  "cat_house_id": 1,
  "cat_name": "Мурзик",
  "cat_house_name": "Большой дом",
  "occupied_at": "2024-01-01T00:00:00Z"
}
```

**Параметры пути:**
- `id` (integer) - ID домика

**Ответ:**
```json
{
  "is_ok": true,
  "result": "Cat house deleted successfully"
}
```

**Коды статусов:**
- `200 OK` - Успешное удаление
- `400 Bad Request` - Неверный ID

### `POST /api/v1/cat-houses/cats/{catId}/add`
Поместить кота в домик.

**Параметры пути:**
- `catId` (integer) - ID кота

**Тело запроса:**
```json
{
  "cat_house_id": 1
}
```

**Поля:**
- `cat_house_id` (integer, required, min 1) - ID домика

**Ответ:**
```json
{
  "is_ok": true,
  "result": {
    "id": 1,
    "cat_id": 1,
    "cat_house_id": 1,
    "cat_name": "Мурзик",
    "cat_house_name": "Большой дом",
    "occupied_at": "2024-01-01T00:00:00Z"
  }
}
```

**Коды статусов:**
- `201 Created` - Успешное размещение
- `400 Bad Request` - Домик заполнен или кот уже находится в домике
- `401 Unauthorized` - Требуется аутентификация
- `403 Forbidden` - Пользователь не является владельцем кота
- `404 Not Found` - Кот или домик не найдены

## 📋 Бизнес-правила

1. **Емкость домика:** Домик имеет фиксированную вместимость (capacity)
2. **Текущая занятость:** Текущее количество котов в домике (current_occupancy)
3. **Свободные места:** available_spaces = capacity - current_occupancy
4. **Один кот - один домик:** Кот может находиться только в одном домике одновременно
5. **Проверка владельца:** Только владелец кота (или администратор) может помещать/удалять кота из домика
6. **Обновление вместимости:** Нельзя уменьшить вместимость домика ниже текущего количества котов
7. **Удаление домика:** При удалении домика все связи с котами удаляются автоматически

## 🔧 Ошибки

### Общие коды ошибок

- `400 Bad Request` - Неверный формат запроса или данные
- `401 Unauthorized` - Требуется аутентификация
- `403 Forbidden` - Доступ запрещен (недостаточно прав)
- `404 Not Found` - Ресурс не найден
- `409 Conflict` - Конфликт данных (например, email уже существует)
- `500 Internal Server Error` - Внутренняя ошибка сервера

### Формат ошибок

Все ошибки возвращаются в стандартном формате:

```json
{
  "is_ok": false,
  "error": "Описание ошибки"
}
```

## 📝 Примечания

- Все даты возвращаются в формате ISO 8601
- Все ID являются целыми числами
- Поля `can_edit` указывают, может ли текущий пользователь редактировать ресурс
- Администраторы имеют полный доступ ко всем ресурсам
- Пользователи могут редактировать только свои собственные ресурсы
- Для домиков для кошек: один кот может находиться только в одном домике одновременно
- Вместимость домика не может быть уменьшена ниже текущего количества котов
